# 模块说明

工程按驱动层和应用层分了两层。驱动层（BSP）管硬件，应用层（App）管控制逻辑，main.c 只做初始化、建任务、启动调度器。

## 分层

- 驱动层（BSP）：电机、灰度、编码器、按键、OLED、串口，每样一个文件
- 应用层（App）：控制逻辑（位置环、速度环、状态机）+ 控制任务和显示任务
- main.c：初始化外设、建任务、启动调度器，控制逻辑都交给 app 层

跑起来是三个任务：controlTask（优先级 2，栈 256 word，10ms 一拍）做控制，uartTask（优先级 1，栈 192 word）从队列里取帧 printf 出去，displayTask（优先级 1，栈 192 word）每 200ms 刷一帧 OLED。串口和显示都排在控制任务之后，不抢它的节拍。

## 各模块

### 电机驱动 bsp_motor.c/h

控制两个直流减速电机的速度和方向，用的是 TB6612 双路驱动。

- Motor_Init()：初始化 PWM，启动顺序是安全的
- Motor_SetSpeed(motor, speed)：设置某个电机的速度，speed 为正转、负反转、0 停，范围 -7200~+7200
- Motor_Stop() / Motor_Brake() / Motor_StopAll()

换方向要按"先关 PWM → 改方向 → 再恢复 PWM"的顺序。不然绕组电感电流不能突变，直接翻方向会产生好几倍堵转电流的尖峰，管子会发热、电源会被拉低。

### 灰度传感器 bsp_gray.c/h

读 8 路数字灰度，算出黑线偏离中线的位置（加权平均）。

- Gray_GetPosition()：返回黑线位置 -7000~+7000，0 是居中，负是偏左，正是偏右；9999 是全白丢线，-9999 是全黑

这个模块用 CD4051 模拟开关选通道，切换通道后必须等 50us 再读，不然 LM393 比较器还没稳定，读出来是错的。我试过把延时注释掉，通道 1 和 5 就互换了。

### 编码器 bsp_encoder.c/h

用定时器编码器模式测左右轮转速（RPM）。

- Encoder_Init()：启动 TIM2/TIM4 编码器计数
- Encoder_GetCount_Left()/Right()：读某轮脉冲数（带符号），读完清零
- Encoder_UpdateSpeed()：每 10ms 采样算一次速度
- Encoder_GetSpeed_Left()/Right()：返回某轮 RPM

参数：4 倍频（TI12），每圈脉冲数 = 减速比 20 × 线数 13 × 4 = 1040。左编码器接 TIM2（A=PA1, B=PA0），右编码器接 TIM4（A=PB6, B=PB7）。左编码器 A/B 相接反过，会导致方向反，这个在调试记录里写了。

### 按键 bsp_key.c/h

PA8 上拉输入的独立按键，用来控制小车启停/状态切换。

- Key_Init()：读当前电平作为稳定态，避免上电误判
- Key_Scan()：非阻塞去抖 + 沿检测，返回"刚按下"的边沿（一次点击返回 1，按住不重复触发）

去抖逻辑：按键电平与当前稳定电平不同时，连续 KEY_WAIT_MS（50ms）保持新电平才确认切换，滤掉机械抖动。用"上次稳定电平 → 本次稳定电平"的变化沿判断是否真的按了一次，所以长按不会反复触发。

### OLED 显示 bsp_oled.c/h

0.96 寸 SSD1306，128x64，4 针 I2C（SCL=PB3，SDA=PB4，地址 0x3C），走软件模拟 I2C。

- OLED_Init()：发初始化命令序列，内部带一次清屏，上电后调用一次
- OLED_Clear()：清空整屏
- OLED_ShowChar(row, col, ch)：在指定行列显示单个 ASCII 字符
- OLED_ShowString(row, col, str)：显示字符串，自动横向排列
- OLED_ShowLine(row, str)：整行覆盖显示，不足 16 字符用空格补齐，不用先清屏
- OLED_ShowNum(row, col, num)：显示有符号整数，自动带正负号

坐标用"行/列"表示，一行 0~3（每行高 16 像素），一列 0~15（每字宽 8 像素）。字模是 8x16 ASCII 点阵，只支持可打印字符（0x20~0x7E），字形取自 VGA 点阵，纵向只占第 2~11 行，四行文本之间才有行距。

改用软件模拟 I2C 是因为硬件 I2C1 在这块板上没落点：默认的 PB6/PB7 是右编码器，重映射的 PB8/PB9 被旧屏那次的 12V 打穿。SCL 和 SDA 都是推挽输出，只有读应答的第 9 个时钟把 SDA 切成输入上拉松开总线。

调用入口在应用层 App_OLED_Show()，由 displayTask 每 200ms 刷一帧，显示状态、目标速度、实测速度、位置偏差。整帧实测约 133ms，200ms 的周期放得下；屏只有这一个任务碰，不需要互斥量。

### 串口打印 bsp_uart.c/h

串口打印从控制任务里挪出来单独做，控制任务只管把要发的一帧塞进队列。

- Uart_Init()：建队列（深度 4，每格 64 字节），启动调度器前调一次
- Uart_Send(frame)：把一帧塞进队列，队列满就直接丢，返回 1 成功 / 0 丢弃
- uartTask：xQueueReceive 阻塞等数据，不占 CPU，拿到一帧 printf 一帧

原来是在控制任务里直接 printf，走到 fputc 会空等 TXE 把一帧发完才返回，几毫秒全算在当拍里。改成入队即走之后，控制任务的当拍时间不再受串口快慢影响。

### 控制层 app.c/h

两层闭环控制都在这里，controlTask 和 displayTask 也放在这个文件。

- controlTask：每 10ms 一拍，依次做 Encoder_UpdateSpeed()、App_State_Update()、APP_Speed_Control()
- displayTask：每 200ms 调一次 App_OLED_Show()
- 位置环（外环）App_Position_Control(pos)：pos 由调用者读好传进来，避免重复读灰度；用 P 控制算出左右轮的目标速度（RPM），靠左右速度不同实现差速转弯
- 速度环（内环）APP_Speed_Control()：用编码器反馈的实际转速，PI 控制让左右轮达到目标速度

积分做了限幅防饱和，目标速度也做了限幅，PWM 同样限幅。不然积分积多了会过冲，低速轮会抖。

### 状态机 App_State_Update()

控制层用显式状态机管理小车行为，由 controlTask 每 10ms 调用一次（和速度环采样节拍一致）。

```
IDLE ──按PA8──→ RUN ──全白──→ LOST
  ▲              │  └──全黑──→ CROSS
  └────按PA8─────┴──────────────┘
```

- **IDLE**：上电默认状态，停车。上电 200ms 内忽略按键（防上电抖动），之后按 PA8 进 RUN
- **RUN**：正常循迹。读灰度 pos：正常压线跑位置环差速；全白（GRAY_ALL_WHITE）进 LOST；全黑（GRAY_ALL_BLACK）进 CROSS
- **LOST**：丢线停车。刚进入时 Motor_BrakeAll() 快速刹车一次，停留时 target=0 保持静止；按 PA8 回 RUN（摆回线上重新起步，不用断电）
- **CROSS**：十字/起跑线停车。逻辑同 LOST，按 PA8 回 RUN

状态切换时的两个关键坑（详见调试记录）：
1. 全黑/全白时 pos 是 -9999/9999，必须先判 pos 再跑位置环，否则会按"极大偏差"算出错误差速，轮子疯转
2. 按键上电瞬间会抖动，IDLE 里要加"上电 200ms 忽略按键"，否则一上电就误进 RUN

## 控制架构示意

```
位置环(外环)                速度环(内环)
灰度 pos ──→ 左右目标速度 ──→ PI ──→ PWM ──→ 电机 ──→ 编码器 ──→ 测速
   ▲                                                 │
   └─────────────────── 反馈 ──────────────────────────┘
```
