# 硬件连接

## 电机（TB6612 双路，D153C）

电机 A 是左轮，电机 B 是右轮。

- 电机 A（左轮）：PWMA = PB1，AIN1 = PB10，AIN2 = PB11
- 电机 B（右轮）：PWMB = PB0，BIN1 = PB12，BIN2 = PB13

电机驱动的 VM 接 DCP3512 的 12V 输出，STM32 板子由 DCP3512 的 5V 供电，STBY 跳线帽接 D153C 上的 3.3V。

## 按键（启停）

- PA8 = key，**上拉输入**，按下接地（GPIO_PULLUP）
- 软件里做 50ms 去抖 + 沿检测（bsp_key.c），上电后 200ms 内忽略按键，防上电抖动误触发

## 灰度传感器（8 路数字）

- AD0 = PA2，AD1 = PA3，AD2 = PA4
- OUT = PA5

VCC 用 DCP3512 的 5V 输出。探头离地大概 18mm 效果最好，这个距离很关键，太近太远都会误判。

## 编码器

- 左编码器：A相 = PA1，B相 = PA0，定时器 TIM2
- 右编码器：A相 = PB6，B相 = PB7，定时器 TIM4

注意：左编码器 A/B 相接反了（A=PA1, B=PA0），这个接法下计数方向是正的。要是调的时候发现方向反，就把 A/B 对调，或者改方向判断。

## 串口（USART1）

- TX = PA9
- RX = PA10

波特率 115200。

## OLED（0.96 寸，SSD1306，4 针 I2C）

- SCL = PB3
- SDA = PB4
- VCC = 3.3V（**千万别接 5V/12V**，会烧片）
- GND = GND

I2C 设备地址 0x3C。驱动方式改成了**软件模拟 I2C**——PB3/PB4 当普通 GPIO 用，自己拉时序，不走 I2C1 外设。

PB3/PB4 出厂是 JTAG 的 JTDO / NJTRST，工程里 `HAL_MspInit()` 调过 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`（JTAG 关掉、SWD 保留），所以这两脚能当普通 IO，ST-Link 下载调试不受影响。

以前接的是 I2C1 重映射的 PB8/PB9（I2C1 默认 PB6/PB7 被右编码器占了，当初才重映射）。这两个脚后来坏了，见下一节。

**注意：** 一定接 3.3V。这块屏我上次接到 12V 直接烧了，万用表量 VCC-GND 变成短路。

## PB8 / PB9（已损坏，不要再接外设）

原来这两脚是 I2C1 重映射给 OLED 用的，现在报废了。

现象：

- 推挽输出高，读回还是 0（同一片 GPIOB 上拿 PB3/PB4 做对照是正常的 0/1）
- 万用表量保持高电平时的实际电压，只有 0.6V 左右
- 断电测电阻：PB8→GND、PB9→GND、PB8↔PB9 全部开路，没有线性的对地通路
- 二极管档测两个方向都导通（拿 PB3 当标尺，健康脚是"红笔 GND / 黑笔脚 = 0.69V，反过来 OL"）

推挽输出高的时候内阻只有几十欧，能把线顶到 3.3V；顶到 0.6V 就说明对地挂着一条低阻通路。电阻档量不出来、二极管档双向导通，说明是**引脚保护结构被打穿，留下了一个正偏结**。

成因大概是旧屏接 12V 那次：如果当时 SCL/SDA 也挂在 PB8/PB9 上，12V 会从屏内部二极管倒灌进这两个脚。F103 引脚的绝对最大值是 VDD+0.3 = 3.6V，12V 足够打穿 ESD 结构。

软件 I2C 也不要往这两脚上跑——推挽持续顶高就是往短路点持续灌电流，会把脚烧掉。

## 其他

- LED = PC13
- 调试口（SWD）：PA13（SWDIO）/ PA14（SWCLK）

## 供电系统

```
12V 锂电池 ──→ DCP3512 电源模块 ──→ STM32 板子 / 电机驱动 / 灰度传感器
```

DCP3512 输入 12V，输出有 4 路 3.3V、4 路 5V、4 路 12V、4 路 ADJ（可调）。板子和灰度用 5V 那路，电机驱动的 VM 用 12V 那路。灰度 VCC 要 5V，别接 3.3V。
